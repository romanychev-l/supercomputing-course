# Весь практикум без доступа к кластеру

Для основной версии курса достаточно обычного компьютера или компьютера в аудитории. **OpenMP работает на ядрах одной машины, MPI можно запускать несколькими процессами на этой же машине.** Отдельные серверы, SSH, GPU и платное облако для обязательных программных заданий не нужны. Это реальное выполнение программ; измерения межузловой сети таким запуском не воспроизводятся.

## Минимальная организация

На студента или пару нужен компьютер с C/C++-компилятором, OpenMP, одной реализацией MPI и Python 3. Если есть всего одно доступное ядро, два MPI-процесса всё равно позволяют проверять сообщения и корректность; ускорение при этом не требуется. При возможности используйте два доступных ядра. Память экономим малыми задачами: массивы N=1,17,101; матрицы сначала 3×3, затем не больше 256×256 или 512×512; halo N=11. Большие размеры нужны только для отдельного опыта производительности.

Если у студентов нет подходящих личных компьютеров, среду готовят на машинах аудитории, работают парами и принимают запуск там. Если доступна только машина преподавателя, пары готовят код и контрольные ответы, затем по очереди запускают и защищают его на этой машине. Это организационный запасной вариант с очередью сдачи, а не обещание каждому полноценной индивидуальной среды. Без какого-либо доступа к компьютеру можно провести теорию и разборы, но не подтвердить самостоятельный запуск программ.

## Linux: Ubuntu/Debian

При возможности установки пакетов подготовьте среду заранее:

```sh
sudo apt update
sudo apt install build-essential python3 openmpi-bin libopenmpi-dev
```

Не нужно одновременно ставить вторую MPI-реализацию ради курса. Если на машине уже есть исправная MPICH, используйте её согласованные mpicc/mpiexec и документируйте выбор. Наличие другого MPI не является ошибкой само по себе. Для Ubuntu 24.04 учтите [известную ошибку пакета MPICH 4.2.0-5build3](https://github.com/actions/runner-images/issues/13204): два процесса могут оба увидеть ранг 0 в мире размера 1. В Linux-инструкции и CI поэтому используем OpenMPI.

Источники пакетов: [Ubuntu: OpenMPI](https://packages.ubuntu.com/noble/openmpi-bin), [Debian: OpenMPI](https://packages.debian.org/openmpi-bin). Проверка на машине аудитории остаётся отдельным шагом; Linux-проверка GitHub Actions не подтверждает конфигурацию каждого компьютера.

## Windows

Практический маршрут — Ubuntu в WSL 2, если это допускается настройками машины. По [инструкции Microsoft](https://learn.microsoft.com/en-us/windows/wsl/install) первоначальная установка запускается из PowerShell с правами администратора:

```powershell
wsl --install -d Ubuntu
```

После необходимых шагов установки/перезапуска команды Linux выполняются **в терминале Ubuntu**, а не в PowerShell. Далее — пакеты и сборка из раздела Linux. Рабочую папку удобно хранить внутри домашнего каталога Ubuntu. WSL не является обязательным требованием к личному компьютеру: если установка запрещена, студент работает на подготовленной машине аудитории. На этом Mac маршрут WSL не проверялся.

## macOS

При уже установленном Homebrew доступны [libomp](https://formulae.brew.sh/formula/libomp) и [MPICH](https://formulae.brew.sh/formula/mpich):

```sh
brew install libomp mpich
```

Если уже установлена Open MPI, оставьте одну согласованную MPI-среду и используйте её mpicc/mpiexec: устанавливать MPICH поверх неё для этих заданий не требуется. Homebrew-пакеты MPICH и Open MPI конфликтуют из-за общих имён инструментов.

Версии библиотеки OpenMP и компилятора должны быть совместимы. Простая команда gcc на Mac может означать Apple Clang, поэтому Linux-флаг -fopenmp сам по себе не гарантирован. Для примера OpenMP:

```sh
cc -Xclang -fopenmp -isystem "$(brew --prefix libomp)/include" \
  -L"$(brew --prefix libomp)/lib" -Wl,-rpath,"$(brew --prefix libomp)/lib" \
  Локально/hello_openmp.c -lomp -o hello_openmp
```

Пример MPI собирается через mpicc, как ниже. Основные эталоны уже проверены на Apple M1 с совместимой временной средой; наличие Homebrew-пакетов на других Mac проверяется отдельно. Не требуется переводить всех студентов на Mac или покупать оборудование.

## Первые два запуска

Все команды ниже выполняются из корня папки практикума. На Linux/OpenMP:

```sh
cc -O2 -Wall -Wextra -fopenmp Локально/hello_openmp.c -o hello_openmp
OMP_NUM_THREADS=2 OMP_DYNAMIC=false ./hello_openmp
```

Ожидается `threads=2`. Если среда реально ограничивает команду одним потоком, это надо явно записать; корректность можно проверять на одном, а измерение параллельного ускорения перенести на машину аудитории.

MPI, на всех подготовленных системах:

```sh
mpicc -O2 -Wall -Wextra Локально/hello_mpi.c -o hello_mpi
mpiexec -n 2 ./hello_mpi
```

Если OpenMPI сообщает, что процессов больше доступных слотов, для этих малых проверок используйте `mpiexec --oversubscribe -n 2 ./hello_mpi`. Это позволяет проверить обмены на одном ядре; измерять ускорение в таком режиме не следует.

Ожидаются ранги 0 и 1 из двух процессов; имя компьютера обычно одинаковое. Строки могут появиться в разном порядке. [Документация MPICH mpiexec](https://www.mpich.org/static/docs/latest/www1/mpiexec.html) описывает запуск процессов. Здесь не требуется hostfile или удалённый вход. Запускать нужно под обычной учётной записью пользователя.

## За что ставится оценка

За корректность, объяснение зависимостей и сообщений, воспроизводимый запуск и разумный эксперимент. Не требуйте одинакового времени у разных компьютеров и ускорения больше единицы. Если нужное число CPU недоступно, студент исследует корректность локально, а недоступный опыт обсуждает по явно обозначенным данным преподавателя. Чужие или учебные цифры нельзя выдавать за собственное измерение.

Job ID, доступ к Slurm, несколько узлов и характеристики межузловой сети **не являются обязательными артефактами локальной сдачи**. За их отсутствие не снимаются баллы. Содержание Slurm изучается по сценарию и диагностическому упражнению; практический опыт работы на настоящем кластере остаётся отдельным результатом, который без такого доступа нельзя честно заявить.
