# Практика 8. Баланс работы и цена общего счётчика

Время: одна пара. Цель: обосновать выбор schedule и способа объединения.

## Часть A. Неравная работа

Вычислить сумму верхнего треугольника A[i,j]=((i+j) mod 17)−8 для 0≤i≤j<N. Сравнить static, dynamic и guided с несколькими размерами блока. Внешний цикл по i имеет неравную длину. Сделать минимум пять повторов, проверить одинаковый ответ. Эталон — режим tri; он поддерживает schedule(runtime), поэтому настройки меняются через OMP_SCHEDULE.

Контроль N=3: элементы −8,−7,−6,−6,−5,−4; сумма −36. Параллельная версия должна учитывать каждый из N(N+1)/2 элементов один раз. При малом N накладные расходы могут доминировать.

## Часть B. Объединение вкладов

Для суммы реализовать четыре корректных варианта: reduction, локальная сумма+atomic, локальная сумма+critical, локальная сумма+lock. Отдельно, как эксперимент цены конкуренции, можно выполнить atomic на каждом элементе. Это разные алгоритмические затраты, их следует назвать явно. Замок инициализируется до parallel и уничтожается после завершения всех потоков.

Все чтения общего изменяемого максимума тоже защищаются. Вариант «проверить max снаружи, затем снова внутри замка» не принимается как корректный. Не требуется демонстрировать гонку как рабочую оптимизацию.

## Сдать

Таблицу времён с N, потоками, schedule/chunk и числом общих обновлений. Дать объяснение, где дисбаланс, где конкуренция, где накладные расходы. Эталон содержит reduction-вариант; остальные студенты реализуют самостоятельно, преподаватель проверяет по независимому ответу и протоколу доступа. Это отмечено явно: автоматический комплект не подменяет проверку всех четырёх исходников.
