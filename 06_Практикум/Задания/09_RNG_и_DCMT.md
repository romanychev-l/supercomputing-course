# Практика 9. Воспроизводимые генераторы и DCMT

Время: одна пара и подготовка параметров заранее. Связь с темой 5 и заданием DCMT рабочей программы.

## Часть A. Логические потоки данных

Генерируйте N чисел с фиксированными блоками по 1024 элемента. Состояние std::mt19937 принадлежит блоку, а не номеру OpenMP-потока. Параметры и seed блока зависят только от фиксированного ID. При изменении OMP_NUM_THREADS и schedule результат должен оставаться тем же. Контрольная сумма, объединяемая XOR, позволяет проверить повторяемость, но не статистическое качество и не отсутствие всех ошибок.

Эталон mt_streams.cpp показывает организацию. Разные seed сами по себе **не доказывают независимость** потоков. Этот пример не называется полноценной реализацией параллельного MT с доказанными непересекающимися подпоследовательностями.

## Часть B. Оригинальная DCMT

В папке «Внешние_библиотеки» сохранена авторская DCMT 0.6.2, архив и лицензия. Соберите `make dcmt`. Выполните `build/dcmt_seq create parameters.txt`, затем `build/dcmt_seq run parameters.txt 1000`. Создание параметров отделено от генерации, потому что поиск может быть дорогим. Пример использует два ID, период 2^521−1 и документированные seed.

Файл содержит версию и поля параметров каждого генератора; это самостоятельные данные, не сырая копия структуры с указателем. При загрузке состояние выделяется заново и инициализируется. Запустите dcmt_omp с 1,2,4 потоками; контрольные суммы по каждому ID должны совпасть с последовательной версией. Не допускайте одновременной записи в одно состояние генератора.

## Сдать и защитить

Код, файл параметров, версии, команды, два повторных запуска и сравнение потоков. Объяснить различие параметров генератора, начального состояния и текущего состояния. Текущий пример сохраняет **параметры для нового запуска**, не checkpoint уже израсходованного потока. Для продолжения потребовалось бы сохранить также state и позицию i. Статистические тесты качества — отдельное расширение; совпадение checksum не является таким тестом.
