# Практика 4. Выполнить задание через очередь

Время: одна пара. Есть два равноправных варианта сдачи по доступному оборудованию. При отсутствии кластера **выбирается вариант Б с той же максимальной оценкой**. Его выполнение не объявляется опытом работы в настоящем Slurm.

## Вариант А. Есть учебный кластер

Требуется учётная запись и инструкция центра. Далее выполняются отправка, контроль и сдача реального задания.

## Условие

Узнайте доступные разделы, лимиты и разрешённый launcher. Соберите программу, подготовьте batch-сценарий, отправьте его sbatch, найдите задание в squeue, дождитесь результата и исследуйте sacct либо доступный аналог. Сохраните job ID, выделенные ресурсы, код завершения, stdout/stderr. На входном узле не выполняйте длительные вычислительные замеры.

Для OpenMP запросите один MPI-процесс и несколько CPU на него. Для MPI — несколько задач и обычно один CPU на задачу. Для гибридного варианта укажите оба уровня. Шаблоны находятся в папке Slurm; partition/account и способ запуска согласуются с центром, заранее не выдумываются.

## Проверка

Фактические процессы/потоки совпадают с запросом. Задание завершается штатно и выдаёт тот же математический результат, что локальная проверка. Разберите состояния PENDING, RUNNING, COMPLETED и хотя бы одну учебную ошибку: неверный путь к исполняемому файлу или сознательно короткий лимит в собственной задаче. Отменять можно только собственное учебное задание.

## Сдать

Сценарий, команды, job ID и журналы. В выводе отличить время ожидания в очереди от времени расчёта. Наличие строки `#SBATCH` в локальном sh-файле само по себе не означает теста планировщика. Преподаватель проверяет сценарий до отправки всей группой и ограничивает первый опыт минутами, малой памятью и минимальным ресурсом.

## Вариант Б. Кластера нет

1. Подготовить два запроса ресурсов: одна OpenMP-задача с двумя потоками и два MPI-процесса по одному CPU. Объяснить nodes/ntasks/cpus-per-task, выбрать небольшой лимит времени и оценить память.
2. Прочитать [учебный CSV](../Локально/учебная_очередь.csv). Это составленные для упражнения данные, не реальные измерения. Для каждой строки объяснить состояние, наличие/отсутствие результата и следующее действие. Найти задачу, в которой число потоков не соответствует выделенному ресурсу.
3. Собрать и выполнить на своей машине два примера из [локального маршрута](../Локально/README.md): hello OpenMP и MPI. Приложить настоящий собственный вывод, версии и команды. На машине с ограниченным ресурсом допускается меньший фактический параллелизм с объяснением.
4. Подготовить batch-сценарий для будущего кластера и проверить его синтаксис через bash -n. Если shell недоступен на личном компьютере, эту часть проверить на машине аудитории. Partition/account/launcher без данных центра оставить явно требующими настройки.

Сдать ресурсные запросы, диагнозы, собственный локальный вывод и сценарий. Job ID не требуется; выдумывать его нельзя. Полная оценка доступна без кластера. Ритм пары: 15 минут запросы, 20 разбор CSV, 35 локальные запуски, 20 обсуждение/сдача. Если среда ещё не готова, пользоваться заранее подготовленным компьютером аудитории.
