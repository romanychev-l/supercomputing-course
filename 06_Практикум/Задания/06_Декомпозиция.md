# Практика 6. Спроектировать алгоритм до написания обменов

Время: одна пара, основная часть на бумаге. Задача: z=max_i min_j A[i,j].

## Условие

Пройдите PCAM: разделите матрицу, опишите независимые локальные минимумы, объединение внешним max, укрупнение и назначение процессам. Укажите память каждого участника и объём пересылок. Нарисуйте граф задач. Сравните разбиение по строкам и по двумерным блокам: какие промежуточные редукции понадобятся во втором случае?

## Контрольные примеры

A=[[3,1,4],[−2,5,0],[7,6,8]] → минимумы [1,−2,6] → z=6. Для A=[[-5,-3],[-8,-2]] результат −5; начальный z=0 обнаруживает ошибку. При p>N часть процессов имеет пустой набор строк и вклад −∞ во внешнюю операцию. Пустая строка в этой постановке не допускается: N≥1.

## Сдать

Две страницы или MD: схема, границы блоков при N=10,p=3, случай p>N, оценка работы и обменов. Программирование необязательно; дополнительный вариант — последовательный проверяющий код. На защите студент объясняет, почему «поровну элементов» не всегда значит «поровну времени». Для треугольной матрицы предложить другой баланс.

Эталон maxmin в kernels использует A[i,j]=((17i+13j) mod 101)−50. Он служит для последующей OpenMP-практики; приведённый выше ручной пример остаётся независимой проверкой смысла операции.
