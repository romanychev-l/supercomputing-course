# Редактируемые презентации и пособия

Сейчас здесь только инфраструктура: общий набор шрифтов, Beamer-шаблон и шаблон пособия. **Ни один из 10 PDF ещё не перенесён.** Карта источников, страниц, актуальных конспектов и целевых путей находится в [materials.json](materials.json); статус каждой темы — `planned`.

Восемь презентаций переносим в Beamer, два текстовых пособия — в article или book с сохранением структуры текста. Шаблоны показывают сборку и набор кириллицы, не заменяют содержимое курса.

## Как переносить тему

1. Согласуйте в issue тему и диапазон страниц. Прочитайте актуальный конспект и исходный PDF. Первичная сверка формул проводится с изображением страницы: текстовый парсер может потерять дроби и степени.
2. Скопируйте [template/main.tex](template/main.tex) или [template-handout/main.tex](template-handout/main.tex) в папку темы по карте materials.json. Общий файл [common/fonts.tex](common/fonts.tex) подключается через `../common/fonts.tex`. Укажите исходных авторов и автора переноса.
3. В начале README темы укажите PDF, авторов, диапазон, статус и карту «страница PDF → слайд/раздел». Перед фреймами/разделами ставьте комментарий `source-page: N`; при разделении одной страницы на несколько слайдов сохраняйте тот же номер.
4. Набирайте текст, формулы и код как текст. Схемы по возможности рисуйте редактируемыми средствами. Оригинальные фотографии можно использовать с указанием происхождения. Не вставляйте целые PDF-страницы как замену LaTeX-исходнику.
5. В CHANGELOG.md темы отдельно фиксируйте исправления ошибок, новые объяснения, объединения/разбиения и пропуски. Исторические данные сохраняйте с датой; обновление оформляйте явным дополнением. В Markdown формулы остаются в Unicode, а в `.tex` используется обычный LaTeX.
6. Соберите тему, проверьте журнал и просмотрите все изменённые страницы. Другой участник сверяет формулы, код, подписи и порядок с оригиналом. Обновите статус в карте: `planned`, `in_progress`, `review` или `done`; `done` требует полного переноса и принятого содержательного/визуального ревью.

## Сборка

После [установки TeX](../docs/LaTeX.md) из корня репозитория:

```sh
make latex
make -C 08_LaTeX pdf DOC=template
```

Результат первой презентации: `08_LaTeX/build/template/main.pdf`, пособия: `08_LaTeX/build/template-handout/main.pdf`. Для новой темы замените `template` её ID, например `03-networks`. Цель `all` автоматически собирает каждую папку первого уровня с main.tex, поэтому новая тема попадёт и в GitHub Actions. Изображения и другие зависимости храните внутри папки темы; команды сборки не должны зависеть от личных абсолютных путей.

PDF в build и вспомогательные файлы игнорируются Git. Артефакты CI позволяют скачать собранные PDF без добавления их в историю. Оригинальные PDF в 01_Лекции_СПбГУ сохраняются неизменными.

## Готовность PR

- Все согласованные страницы учтены в карте; нет скрытых пропусков и несогласованных содержательных изменений.
- Формулы, код и основной текст редактируются. Исправления оригинала объяснены и согласованы с актуальным конспектом.
- Сохранены авторство и источники изображений.
- Сборка проходит без ошибок; предупреждения о переполнении устранены или конкретно объяснены.
- Визуально проверены кириллица, формулы, индексы, обрезка, читаемость кода и схем.
- PR содержит команды и результат проверки, скриншоты изменённых страниц и имя проверяющего. Использование агента описано честно.
