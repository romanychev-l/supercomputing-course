# MPI: путеводитель по текстовому пособию

Источник: [hpc-lec07-mpi-text.pdf](../01_Лекции_СПбГУ/hpc-lec07-mpi-text.pdf), 35 страниц PDF. Это связное пояснение к трём наборам MPI-слайдов, не отдельные 35 лекций. Для синхронного листания используйте конспекты [основ](06_MPI_Основы.md), [обменов](07_MPI_Обмены_и_типы.md) и [топологий](08_MPI_Коммуникаторы_и_топологии.md). Подготовлено 30.10.2026.

## PDF 1–2. Оглавление

Оно задаёт три последовательных уровня: основа сообщений, расширенные операции и организация участников. Не начинайте с редких режимов отправки. Сначала студент должен объяснить свой локальный массив и соответствие Send/Recv. Маршрут для преподавателя — чтение перед соответствующими двумя-тремя парами, а не пересказ подряд всей главы.

## PDF 3–4. Модель и понятия

MPI является стандартом; конкретная библиотека его реализует. Процессы имеют собственные адресные пространства и общаются в контексте коммуникатора. Одинаковый tag в разных коммуникаторах не смешивает сообщения. Тип данных описывает значения и их расположение, а виртуальная топология — соседство. Формулировка «intercommunicator — глобальный коммуникатор» неточна: он связывает две группы и не обязан включать все процессы.

## PDF 5–8. Первые программы

MPI_Init, Comm_size, Comm_rank и Finalize образуют каркас. В исходнике встречается agrc вместо argc — нужно исправить. Count в Send/Recv измеряется элементами типа. Отправляющий tag неотрицательный и ограничен MPI_TAG_UB. На приёме можно разрешить любой источник/тег, но это меняет допустимый порядок обработки. Блокирующий Send освобождает отправляющий буфер для повторного использования, не доказывая завершения пользовательской работы получателя. Для p=1 первая программа должна завершаться без обращения к рангу 1.

## PDF 9–10. Время и Bcast

Настенные часы измеряют локальную длительность; часы разных узлов не вычитают друг из друга. Для времени всей фазы берут максимум локальных длительностей. Bcast вызывают все участники выбранного коммуникатора; у root буфер источник, у остальных приёмник. Успешное завершение позволяет использовать локальный буфер, но не означает обязательного полного барьера. Рассылка всего массива ради небольшой локальной части — учебное упрощение с ценой памяти.

## PDF 11–13. Reduce и барьер

Reduce выполняет поэлементную операцию над вкладами всех процессов и даёт итог корню. Для [1,2] и [10,20] SUM даёт [11,22], а не четыре элемента. Если полный набор исходных вкладов нужен дальше, используйте Gather. Allreduce нужен, когда итог нужен всем. Floating point допускает разные последние разряды при другом дереве сложения. Barrier согласует вход всех участников, но не заменяет завершение неблокирующих запросов.

## PDF 13–16. Режимы и неблокирующее исполнение

Standard, synchronous, buffered и ready имеют разные условия завершения. Относительную скорость стандарт не обещает; ready требует заранее начатого приёма. Isend/Irecv отделяют начало от завершения. Между ними можно выполнять только независимую работу с соблюдением ограничений на буферы. Wait/Test фиксируют завершение; без него нельзя менять отправляющий массив или читать принимаемый. Sendrecv удобен для обмена соседей и избегает опасного порядка «все сначала отправляют». Неблокирующий вызов сам по себе не гарантирует реального перекрытия передачи вычислениями.

## PDF 16–20. Коллективы

Scatter раздаёт части, Gather собирает, Allgather собирает всем, Alltoall перераспределяет отдельные блоки каждому. В Scatter sendcount и в Gather recvcount задаются на одного партнёра. Для неравных частей нужны варианты с v. Scan формирует префикс в порядке рангов; [1,2,3,4] при SUM превращается в [1,3,6,10]. Reduce_scatter сочетает агрегирование и раздачу частей. Ошибка выбора коллектива часто логическая, даже когда код успешно собирается.

## PDF 21–25. Типы и упаковка

Карта типа описывает базовые типы со смещениями; сигнатура — только последовательность типов. Size измеряет полезные данные, extent — шаг повторения. Для столбца C-матрицы используется vector(rows,1,cols,MPI_DOUBLE,…), где stride — расстояние между началами блоков. Современные имена: MPI_Type_create_struct, MPI_Type_create_hvector/hindexed, MPI_Type_get_extent, MPI_Get_address. В обычном MPI_Type_size выход имеет тип int*. Коммит обязателен перед коммуникацией. В Pack/Unpack передаются адреса скаляров, фактическая длина упакованного сообщения — конечное position. В исходнике встречаются ошибки этих форм, поэтому перед запуском опирайтесь на исправленный конспект и эталоны.

## PDF 26–27. Группы и коммуникаторы

Группа — упорядоченный набор участников; коммуникатор добавляет контекст. Split делит по color и упорядочивает по key, причём мировой номер может измениться. При исключении участника получают NULL и не вызывают в нём коммуникации. Group_excl принимает число исключаемых рангов. Не все функции создания коммуникаторов имеют одинаковую область коллективного участия; в базовом примере используем общий Comm_split, вызываемый всеми исходными участниками.

## PDF 28–29. Декартовы сетки

Dims задаёт размеры, periods — замыкание границ, reorder разрешает изменение рангов. Правильное написание функций — Cart, не Card. Cart_shift только возвращает соседей, после него выполняется обмен. В непериодической сетке отсутствующий сосед обозначается MPI_PROC_NULL; соответствующая граничная ячейка должна иметь заданное значение. Это позволяет писать один протокол для крайних и внутренних процессов.

## PDF 30–31. Граф и Fortran

Для звезды из пяти вершин степени [4,1,1,1,1], но MPI_Graph_create требует накопленный index=[4,5,6,7,8]. Это существенная ошибка исходного примера. Edges=[1,2,3,4,0,0,0,0]. Типовая проверка — получить соседей обратно и сравнить все списки. Fortran-часть описывает старые привязки; для нового кода изучают mpi_f08 при доступной поддержке. Использование C API из C++ остаётся нормальным современным маршрутом.

## PDF 32–33. Запуск, расширения, обзор

Параметры launcher зависят от реализации, старое -localonly не является универсальным. В кластере MPI запускается в выделенном ресурсе по инструкции центра. Возможности MPI-2 на слайде — исторический обзор; текущий стандарт проверен отдельно. Для вводного курса важнее корректный halo exchange и воспроизводимое время, чем перечисление RMA/MPI-IO без практики. Литература остаётся источником методики, а точный API сверяют с документацией.

## PDF 34–35. Вопросы и задания

Есть задачи на базовые агрегаты, сравнение режимов, неблокирующие операции, Sendrecv, коллективы и типы. Они уже сохранены в самостоятельном [каталоге заданий MPI](../06_Практикум/Исходные_задания/MPI.md). Расширенные условия добавляют проверку p=1, неравного разбиения и ограничения p≤N для сеточного эталона. Автоматическая проверка включает тайм-аут и сравнение с независимым последовательным расчётом. Тайм-аут обнаруживает отсутствие завершения, но не является доказательством свободы от всех возможных взаимоблокировок.

## Устный мини-зачёт перед лабораторной

1. Когда разрешено изменить буфер Isend? После завершения запроса.
2. Что делает Gather с двумя векторами? Размещает подряд по рангам, не суммирует.
3. Что определяет ранг? Его коммуникатор, а не глобальное физическое место.
4. Что даёт Cart_shift? Ранги соседей, без пересылки данных.
5. Почему маленький тест Send→Recv у всех мог пройти, а большой завис? Корректность ошибочно зависела от внутренней буферизации.
