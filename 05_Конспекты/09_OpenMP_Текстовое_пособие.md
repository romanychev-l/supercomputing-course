# OpenMP: путеводитель по текстовому пособию

Источник: [hpc-lec05-openmp-text.pdf](../01_Лекции_СПбГУ/hpc-lec05-openmp-text.pdf), 49 страниц PDF. Это глава книги, а не ещё одна самостоятельная лекция. Печатные страницы 125–172 соответствуют PDF 1–48; PDF 49 почти пустая. Для листания презентации используйте [отдельный конспект](04_OpenMP_с_переводом.md); здесь дан маршрут чтения главы с пояснениями. Подготовлено 30.10.2026.

## PDF 1–3. Введение

Общая память позволяет потокам взаимодействовать через объекты одного процесса. OpenMP снижает объём служебного кода, но не снимает ответственность за зависимости. Инкрементальность означает возможность начать с одного дорогого цикла. Прежде чем добавлять директиву, определите последовательный контрольный результат и границы измеряемой фазы. Это создаёт основу для дальнейшего сравнения.

## PDF 4–6. Потоки, взаимодействие и структура

Команда исполняет параллельную область, затем объединяется в последовательное продолжение. Реализация может переиспользовать системные потоки. Общая переменная — один объект, доступный нескольким участникам; локальная — отдельный объект каждого. Если два потока одновременно делают s+=x, каждый выполняет чтение, арифметику и запись. Возможна потеря обновления, а в модели языка конфликт без синхронизации является гонкой. Три части OpenMP: директивы, функции библиотеки и окружение запуска.

## PDF 7–10. Parallel и первый пример

Весь блок parallel выполняется каждым участником. Наличие обычного for внутри не распределяет его автоматически. Номер узнают через omp_get_thread_num, фактический размер команды — omp_get_num_threads внутри области. Формат C-программы нужно исправить до современного int main, с подходящими заголовками и printf. Время измеряют omp_get_wtime на одном измеряющем потоке, а не суммой процессорных времён всех участников. Порядок строк hello может меняться, и это само по себе не ошибка.

## PDF 11–15. For, объединённая форма и schedule

Worksharing делит итерации между имеющимися потоками. Parallel for одновременно создаёт команду и делит цикл. Для суммы строк локальный аккумулятор обнуляют на каждой строке и сохраняют результат в отдельный элемент массива. В исходных примерах встречаются int sum при float-данных и %f для int: это реальные ошибки, их нельзя переносить. Static удобен для одинаковой цены строк; dynamic/guided помогают при неравномерной работе ценой диспетчеризации. Начальный размер блока подбирают экспериментом, не предполагая заранее победу dynamic.

## PDF 16–17. Ordered, nowait и if

Ordered позволяет получить результаты по номерам итераций: работа до него идёт параллельно, а печать внутри ordered — в порядке исходного цикла. Например, суммы строк могут быть вычислены в порядке 2, 0, 1, но напечатаны по строкам 0, 1, 2. На слайде 66 презентации тот же смысл показан через 2 печати: No order и Order. Nowait убирает выходной барьер конкретного worksharing, но не обязательный барьер конца parallel. Убирать ожидание можно только при отсутствии зависимости от незавершённой работы других. If позволяет избежать затрат параллельного исполнения маленького объёма. Книжные фигурные скобки между parallel for и for надо исправить: директива должна относиться непосредственно к циклу. Печать не включайте в измерение арифметического ядра.

## PDF 18–20. Атрибуты и редукция

Private не копирует исходное скалярное значение, firstprivate копирует, lastprivate возвращает логически последний экземпляр. Lastprivate не складывает результаты участников. Для общей суммы нужна reduction(+:sum). В примере sum=0, i=0…99 контрольный результат 4950. Если исходная sum=10, ожидается 4960, потому что начальный общий вклад также учитывается. Указатель firstprivate остаётся адресом общей памяти, поэтому это не независимая копия массива. Для floating point фиксируйте допуск и объясняйте влияние порядка.

## PDF 21–25. Atomic, critical, lock

Для одного total += sum подходят и atomic update, и critical: atomic обеспечивает неделимость поддерживаемого обновления total, critical пропускает потоки в защищённый блок по очереди. Если добавление стоит после каждой строки, оба варианта обновляют общую total 1 раз на строку. Reduction(+:total) меняет организацию накопления: каждый поток складывает суммы своих строк в приватной total, затем OpenMP объединяет частичные результаты. Можно накопить вклад потока вручную и добавить его через atomic или critical 1 раз: частоту общих обновлений задаёт алгоритм. [Сравнение на одном примере](04_OpenMP_с_переводом.md#слайд-55-сумма-через-atomic).

Lock позволяет явно управлять критическим доступом. Для максимума вместе с индексом требуется согласовать проверку и запись пары. **Два if в примерах 5.9 с critical и 5.10 с lock написаны намеренно:** автор на книжной странице 147 прямо объясняет, что внешний if сокращает число входов под защиту, а внутренний перепроверяет максимум после ожидания. Например, поток с sum=20 прошёл внешнюю проверку при smax=10, но другой успел записать 30; повторная проверка не даст заменить 30 на 20. Вторая проверка необходима при такой организации кода.

Ограничение показанной реализации относится к внешнему чтению обычной общей smax без синхронизации с записями других потоков. Это гонка по модели памяти OpenMP; само наличие 2 if ошибкой не является. Простое исправление — сравнение и обновление целиком под одной защитой. Сохранить оба if можно, обеспечив атомарные обращения к smax, включая запись под замком; пример и источники приведены на [слайдах 53](04_OpenMP_с_переводом.md#слайд-53-максимум-сумм-строк) и [58 расширенного конспекта](04_OpenMP_с_переводом.md#слайд-58-замок-и-двойная-проверка). Эти же книжные фрагменты включены в презентацию на PDF 53 и 58. Инициализация и уничтожение замка выполняются вне периода конкурентного использования.

## PDF 26–28. Sections

Каждая секция выполняется один раз. Две секции не используют произвольное число потоков одинаково эффективно: параллелизм ограничен числом независимых блоков. Если одна секция производит данные для другой, потребуется отдельный безопасный протокол передачи готовности. Само соседство блоков не создаёт конвейера. Для независимых сумм строк for обычно проще. В конце PDF 28 начинается обсуждение single/master: первый выбирает одного участника, второй — основного.

## PDF 29–30. Барьер, flush, threadprivate

Barrier — ожидание всей команды между этапами: например, каждый заполнил свою часть массива, после барьера можно использовать весь готовый массив. Flush касается другого вопроса: согласования обращений потока с общей памятью. Он сам не заставляет всю команду встретиться и ждать. Так различаем готовность этапа и видимость данных. Threadprivate делает глобальный/статический объект отдельным для потока; сохранение между командами имеет условия. Copyin применяется как параметр parallel, не самостоятельная директива. В начальном коде предпочитайте локальные переменные и явные понятные механизмы синхронизации.

## PDF 31–33. Управление командой

Запрашиваемый и фактический размер могут различаться. Число доступных процессоров также не обязано совпадать с ресурсом, который пользователь имеет право занять. На кластере опирайтесь на allocation. Для эксперимента фиксируйте OMP_NUM_THREADS и OMP_DYNAMIC, узнавайте реальный размер команды. Вложенный параллелизм может случайно многократно увеличить число потоков. Старые функции управления вложенностью рассматриваются как историческая форма; для углубления сверяйте актуальную спецификацию.

## PDF 34–37. Fortran и сборка

Синтаксис директив и закрывающих конструкций отличается, модель данных и зависимостей сохраняется. Если курс ведётся на C/C++, Fortran можно оставить обзорным чтением. Перечень компиляторов и флагов старый; реальные команды берут из документации установленной версии. Для GCC обычно нужен -fopenmp, но Apple Clang под именем gcc на Mac не обязан поддерживать такой рецепт. В нашем Makefile последовательная и OpenMP-сборка используют один исходник с условными фрагментами по _OPENMP.

## PDF 38–40. Итоги, литература и вопросы

Проверяйте понимание через объяснение кода: почему независимы строки, где живёт sum, когда можно читать итог. Ответ «переменная общая, значит безопасна» ошибочен. Полезная защита занимает пять минут и включает изменение размера и числа потоков. Умение назвать все функции по памяти не заменяет объяснение зависимости. Книги дополняют обучение, а допустимость синтаксиса устанавливает документация.
