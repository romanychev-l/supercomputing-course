# Как улучшать курс

Начните с [инструкции для первого PR](docs/Первый_PR.md) и [списка задач](TODO.md). Для маленькой опечатки отдельный issue необязателен. Для формулы, новой темы, изменения практики или переноса презентации сначала согласуйте объём в issue. Один PR должен решать одну понятную задачу.

## Что положить в PR

- Конкретная проблема и новое поведение: файл, тема, страница/номер слайда, пример до и после.
- Объяснение и первичный источник для содержательного исправления. Для формулы — определения, размерности, допущения и предельные случаи.
- Реальные команды проверки и результат. Если чего-то не запускали, укажите это прямо.
- Для LaTeX — исходники, соответствие страницам оригинала, перечень расхождений и скриншоты изменённых страниц. PDF из build не коммитьте; сборка шаблона доступна в артефакте Actions, новые папки тем с main.tex автоматически включаются в сборку.
- Если помогал агент — что ему поручили и что автор PR проверил самостоятельно. Автор должен объяснить правку на занятии.

Сошлитесь на задачу: `Closes #N`, только если PR завершает её целиком; для части работы используйте `Refs #N`. Начинайте Draft PR, если нужна ранняя обратная связь. Отвечайте на замечания в той же ветке.

## Проверки

```sh
python3 tools/check_materials.py
make practice-serial
```

Вторая команда нужна при изменениях последовательных C/C++-программ или Python-эталонов. Для OpenMP, MPI и DCMT выполните `make practice` в совместимой среде; детали — в [практикуме](06_Практикум/README.md). Для LaTeX используйте [инструкцию](docs/LaTeX.md), соберите и просмотрите изменённые страницы. Не требуйте ускорения на каждом компьютере: сначала корректность и воспроизводимость.

GitHub Actions повторяет проверку материалов, полную практику на Linux и сборку LaTeX-шаблона. Это не проверка нескольких узлов или реального Slurm. Файлы PDF, DOCX и XLSX исходного комплекта проверяются по контрольным суммам.

## Правила материалов

Соблюдайте [AGENTS.md](AGENTS.md). Не заменяйте исходные PDF. В Markdown формулы записываются Unicode и дробями через `/`; в `.tex` используется LaTeX. Сохраняйте блоки «ГОВОРИМ», «ЗНАТЬ, НО НЕ ГОВОРИТЬ» и «Оригинал на слайде».

Не добавляйте локальные бинарники, ZIP-раздачи, служебные настройки и большие результаты экспериментов. Примеры результатов допускаются, когда они малы, объяснены и нужны для обучения. Сохраняйте авторство и лицензии заимствованного кода и изображений.

## Работа с агентом

Пример задания:

> Прочитай AGENTS.md и issue. Проверь слайды 8–12 в актуальном конспекте, сверяя формулы с изображением оригинальных страниц. Сделай только согласованную правку. Запусти подходящие проверки. Перечисли найденные расхождения, источники и непроверенные вопросы. Не выдумывай результаты.

Перед отправкой самостоятельно прочитайте diff (`git diff` и `git diff --staged`). Не принимайте исправления формул только потому, что агент написал уверенное объяснение. Обсуждайте спорные вопросы по существу и уважительно.
